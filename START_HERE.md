# START HERE — Yaros Strong River Compass

Read this before starting or reviewing development.

## 60-second compass

**North Star:** make the factory better, not just the local product.

**Current sequence:**

`INTENT -> READ-BACK -> FREEZE -> REUSE CHECK -> CORE GAP -> BUILD MODULE -> E2E PILOT -> EVIDENCE -> ANTI-SALYM -> LESSON -> FACTORY vNEXT`

## Pareto

The priority is the 20% of mechanisms that accelerate the next 80% of work:

1. Universal Core/API contracts
2. Adapter SDK
3. AI Gateway / common AI OS
4. Sandbox + automated evidence
5. One proven reference end-to-end flow

## WIP limit

At the same time we allow only:

- 1 factory/system bottleneck;
- 1 reference end-to-end flow;
- 1 next adapter after the reference.

Do not open another similar initiative before the current flow reaches PROVE.

## Strong River test

Before approving work ask:

- Does it strengthen shared Core or create another stream?
- Is it reusable by 2+ products?
- Does it remove manual work or duplication?
- Is there measurable evidence?
- Is product-specific logic leaking into Core?

## Anti-Salym stop conditions

SCALE BLOCKED when any critical condition is true:

- Platform Trap
- Fake Reuse
- Mega-Core
- Human Bottleneck
- Evidence Theater
- Adapter Leakage
- AI Leakage
- Local Fix without prevention

## Two-proof rule

A component becomes shared Core only when:

1. two independent products/adapters use it;
2. the second integrates without rewriting the first;
3. time/cost/risk reduction is measured.

## Management question

Do not ask only: **What did the programmer finish?**

Ask: **What did this work make faster or safer for the next 5–10 tasks?**

## Daily decision

`RIVER = continue`

`CLOUD = rework before continuing`

`LOCAL STREAM = stop and reconnect to shared architecture`
